# Правила командной работы с репозиторием

## Ветки

* `main` — только проверенный код, напрямую не коммитим;
* рабочая ветка одного модуля — `feature/<модуль>`, создаётся от `main`;
* исправление ошибки — `fix/<модуль>`.

## Коммиты

Формат сообщения: `<тип>(<модуль>): что сделано`.

| Тип | Когда используется |
|---|---|
| `feat` | новый код модуля |
| `fix` | исправление ошибки |
| `docs` | документация |
| `chore` | служебные изменения (сборка, настройки) |
| `test` | проверки и тесты |
| `merge` | слияние ветки в `main` |

Сообщение пишем по-русски, в повелительном наклонении, без «поправил немного».

## Слияние и проверка

1. Модуль готов — ветка отправляется на сервер: `git push -u origin feature/<модуль>`.
2. Интегратор вливает ветки в `main` по одной: `git merge --no-ff feature/<модуль>`.
3. После каждого слияния проверяется сборка и совместимость модулей.
4. Конфликт разрешается вручную; в коммит слияния пишется, что именно конфликтовало.
5. Готовый `main` отправляется на сервер: `git push origin main`.
